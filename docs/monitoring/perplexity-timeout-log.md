## Scheduler-drift trend (separate from the timeout fix)

First-fetch time crept later 09-08 through 09-14 (14:30-14:34 -> 17:26 -> 19:27), then improved somewhat on 09-15 (18:16) and 09-16 (18:13), held steady on 09-17 (18:19), then improved again on 09-18 (17:43), 09-19 (17:18), and roughly held on 09-20 (17:30) -- then jumped back up to 19:33 on 09-21 (close to the 09-14 peak), before dropping back to 18:08 on 09-22. The 09-21 spike looks like a one-off rather than the start of a new trend -- 09-22 through 09-27 (18:08, 18:26, 18:27, 18:42, 17:46, 18:29) have all landed in a normal, fairly tight band, confirming 09-21 was an outlier. Then 09-29 through 10-02 settled into a new elevated band (~19:23-19:36 UTC), which itself broke on 10-03/10-04 (back to ~18:00 UTC). Two zero-run-in-window incidents have now occurred (09-28, 10-05), each resolved cleanly within hours once a run did fire, with no Perplexity or auth problems either time. Escalation threshold: flag the user if first-fetch drifts past 20:00 UTC (risking the day's fetch not landing inside the window at all), if a same-day retry drifts past 23:12 UTC (matching/worse than 09-14), or if a day fails to produce any commit at all.
